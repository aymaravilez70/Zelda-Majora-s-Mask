Quiero desarrollar un proyecto experimental para ejecutar The Legend of Zelda: Majora's Mask directamente en un navegador web.

IMPORTANTE:

* Tengo una copia/ROM del juego obtenida legalmente y quiero usarla únicamente para mi propio proyecto experimental.
* NO quiero crear una página que simplemente permita descargar la ROM.
* Quiero que el resultado final sea una experiencia tipo:

  https://miweb.com/zelda

  El usuario entra al enlace y puede comenzar a jugar directamente desde el navegador.
* No quiero que el usuario tenga que instalar un emulador, descargar un ejecutable ni realizar configuraciones manuales.
* Quiero minimizar al máximo cualquier pantalla de carga inicial.
* No quiero una solución basada en streaming de video/cloud gaming. El juego debe ejecutarse localmente en el navegador.

OBJETIVO TÉCNICO

Investiga primero cuál es actualmente la mejor arquitectura para ejecutar Majora's Mask de Nintendo 64 en navegador.

Evalúa especialmente:

1. WebAssembly (WASM)
2. Emscripten
3. WebGL / WebGPU
4. Emulación de Nintendo 64 en navegador
5. Proyectos de decompilación/reimplementación de Majora's Mask
6. Posibilidad de compilar un port nativo del juego para WebAssembly
7. Sistemas de caché y almacenamiento local del navegador para evitar descargas repetidas
8. Service Workers y Cache API
9. Compresión y carga eficiente de assets

NO quiero que simplemente me digas "usa un emulador". Quiero que determines cuál de estas arquitecturas ofrece mejor rendimiento y experiencia.

IMPORTANTE SOBRE LA CARGA

Quiero que analices honestamente qué significa "entrar y jugar inmediatamente".

No quiero que me prometas que es posible cargar varios cientos de MB mágicamente sin transferir datos.

Si el navegador necesita descargar archivos, diseña la arquitectura para:

* minimizar la descarga inicial;
* comprimir archivos;
* dividir recursos en chunks;
* cargar primero lo indispensable;
* cargar recursos adicionales mientras el usuario ya está jugando cuando sea técnicamente posible;
* utilizar Service Worker;
* utilizar Cache API / IndexedDB cuando corresponda;
* aprovechar HTTP caching;
* mostrar una pantalla de carga mínima y profesional únicamente cuando sea inevitable.

Quiero que determines cuál es el tamaño razonable de la carga inicial y cuál sería el tamaño total aproximado del proyecto.

LEGAL

No quiero distribuir públicamente archivos protegidos por copyright que no tenga derecho a redistribuir.

Diseña el proyecto de forma que:

* el runtime/código que pueda distribuirse legalmente esté separado;
* los archivos propietarios del juego no se incluyan en un repositorio público;
* quede claro qué archivos debo proporcionar yo localmente;
* si una parte del proceso requiere que yo coloque mi propia copia del juego, indícame exactamente dónde.

NO quiero que inventes una solución.

Si una tecnología no permite hacer algo, dilo claramente.

Si existe un proyecto open source/decompilación/reimplementación que facilite muchísimo el proceso, identifícalo y explícame:

* qué hace;
* qué licencia tiene;
* qué archivos proporciona;
* qué tendría que aportar yo;
* si puede compilarse a WebAssembly;
* qué tan difícil sería adaptarlo al navegador.
